Harmonica MCP lets AI agents create and interact with deliberation sessions.
The hosted endpoint in Harmonica Pro is the primary implementation and the
recommended connection for new integrations.

There are two ways to connect. The **hosted endpoint** needs nothing installed and is the
simplest option for a client that supports remote MCP servers. The **npm package** runs
locally over stdio for clients that require it and for OSS/self-hosted REST API
instances. The [npm compatibility package](https://github.com/harmonicabot/harmonica-mcp)
receives security and compatibility fixes; new MCP capabilities are developed in
Pro and are not automatically backported. Existing local connections remain
supported, with no deprecation date set.

## Hosted endpoint

Point any client that supports remote MCP servers at:

```
https://app.harmonica.chat/api/mcp/mcp
```

The transport is streamable HTTP. Every request must be authenticated. Send the same
`hm_live_...` API key from [Get an API key](#1-get-an-api-key) as a bearer token:

```
Authorization: Bearer hm_live_your_key_here
```

<CodeGroup>

```bash Claude Code (bash)
claude mcp add-json harmonica '{"type":"http","url":"https://app.harmonica.chat/api/mcp/mcp","headers":{"Authorization":"Bearer ${HARMONICA_API_KEY}"}}' -s user
```

```json Claude Code config
{
  "mcpServers": {
    "harmonica": {
      "type": "http",
      "url": "https://app.harmonica.chat/api/mcp/mcp",
      "headers": {
        "Authorization": "Bearer ${HARMONICA_API_KEY}"
      }
    }
  }
}
```

```json OpenCode V2 config
{
  "mcp": {
    "servers": {
      "harmonica": {
        "type": "remote",
        "url": "https://app.harmonica.chat/api/mcp/mcp",
        "oauth": false,
        "headers": { "Authorization": "Bearer {env:HARMONICA_API_KEY}" }
      }
    }
  }
}
```

</CodeGroup>

Load `HARMONICA_API_KEY` into the environment that starts your client and keep it
available after restarting the client. These examples store a variable reference,
not the key. Environment-reference syntax differs by client; the
[Claude Code](https://code.claude.com/docs/en/mcp#environment-variable-expansion-in-mcp-json)
and [OpenCode V2](https://opencode.ai/v2/docs/mcp-servers/) references document the
respective syntax above. OpenCode V1 places `harmonica` directly under `mcp`
instead of `mcp.servers`. Check the live connection in your client after setup;
registration alone does not prove authentication works.

Signing in with your Harmonica account instead of pasting a key is not available yet, so an
API key is currently the only credential the hosted endpoint accepts.

The core tools below are shared with the npm package. Tools explicitly marked
**hosted only** run in the application runtime and are not available in the npm adapter.

### Host chain control (hosted only)

Use `get_chain_state` with any `session_id` in a chain. It returns the current
step ID, stable session/step IDs, assignment thresholds or timer readiness, and
actionable blockers. Owner/admin access to the origin session is required;
owning a later step or being a project editor alone is not enough.

When `can_advance` is true, call `continue_chain` with that `session_id` and the
returned `current_step_id` as `expected_step_id`. Eligibility is checked again
under the runtime lock. There is no force or completion override. If a blocker
is `summary_required`, use `generate_summary` for the listed session, then
inspect again. Completion and role blockers must be resolved normally.

Retry an uncertain request with the **same** expected step ID. A committed
request returns its original receipt with `replayed: true`, without creating
another session or sending the transition's notifications again. Inspect state
again before advancing a different step, since normal automatic gates may have
caught up further. Normal progression can reserve credits and email assigned
roster participants. Platform metadata audit keys cannot advance a chain.

## Standalone stdio setup (compatibility)

Use this path when your client requires stdio or you connect to an OSS/self-hosted
Harmonica REST API. It requires Node.js 20 or newer. For a self-hosted instance,
set the server's `HARMONICA_API_URL` to its base URL without `/api/v1` (for example,
`http://localhost:3000`). The npm adapter calls that instance's REST API.

An existing stdio registration can stay in place. Switching to hosted MCP is an
explicit configuration change: record the current configuration before replacing
it, keep the account's key in your launch environment, and verify the hosted
connection before removing the old setup. Point self-hosted clients at their own
instance rather than switching them to Pro's hosted endpoint.

### 1. Get an API key

1. [Sign up for Harmonica](https://app.harmonica.chat) if you haven't already (free)
2. Go to your [Profile](https://app.harmonica.chat/profile) > **API Keys** > **Generate API Key**
3. Copy your `hm_live_...` key — it's only shown once

### 2. Configure your AI tool

Add the server to your AI tool's MCP config:

<CodeGroup>

```json Claude Code (~/.claude.json)
{
  "mcpServers": {
    "harmonica": {
      "command": "npx",
      "args": ["-y", "harmonica-mcp"],
      "env": {
        "HARMONICA_API_KEY": "hm_live_your_key_here"
      }
    }
  }
}
```

## Available tools

| Tool | Description |
|------|-------------|
| `create_session` | Create a new deliberation session and get a shareable join URL |
| `update_session` | Update session metadata (topic, goal, context, critical, prompt) |
| `close_session` | Close a session without deleting participant threads, messages, summaries, or other data |
| `reopen_session` | Reopen a completed session so participants can join or continue again |
| `list_sessions` | Paginate sessions by status. Keys explicitly authorized by a current global admin can request platform-wide metadata; per-session content and mutations remain account-scoped. |
| `get_session` | Get full details of a session (includes facilitation prompt) |
| `get_chain_state` (hosted only) | Inspect stable chain/step/session IDs and actionable completion, role, and predecessor-summary blockers; requires origin-session owner/admin access |
| `continue_chain` (hosted only) | Advance through the normal runtime using `session_id` and `expected_step_id`; owner/admin only, no force bypass, replay-safe with actor audit evidence |
| `get_questions` | Get pre-session questions (data collection form) |
| `get_responses` | Get participant responses |
| `get_summary` | Get the AI-generated summary |
| `search_sessions` | Search sessions by topic or goal |
| `list_telegram_groups` | List Telegram groups registered to your account |
| `list_meetings` | List owned calendar meetings with compact transcript currentness and processing metadata |
| `get_transcript` | Get one bounded transcript page with `turns` or `text` format and an optional continuation cursor |
| `get_meeting_restrictions` | Get effective processing restrictions and append-only history for an owned meeting |
| `update_meeting_restrictions` | Set owned-meeting restrictions or review a pending restriction candidate |
| `create_project` | Create a project (workspace) you own |
| `publish_sensemaking_topic` | Publish a project as a public sensemaking topic (the `/explore` hub + `/t/[slug]` page) |

### Meeting transcript paging

`get_transcript` returns one page only. It defaults to at most 100 segments and
25,000 transcript characters, with hard maxima of 200 segments and 50,000
characters. Pass `pagination.next_cursor` back as `cursor` to continue; the tool
never accumulates the rest of a transcript automatically. If the transcript
changes between pages, restart without a cursor.

Use `format: "turns"` for structured speaker segments or `format: "text"` for a
plain-text rendering. Speaker labels come from the recording provider and are
not verified identities across meetings. `include_speaker_email` is owner-only
and applies only to turns format. Complete transcript download remains an
owner-only REST export and is intentionally not an MCP tool.

## Example prompts

Once connected, try these prompts with your AI agent:

- *"Create a Harmonica session about team retrospective with the goal of reviewing Q1"*
- *"List my active Harmonica sessions"*
- *"Show me the summary for session [id]"*
- *"What did participants say in the remote work session?"*
- *"Search my sessions about governance"*
- *"Show me the facilitation prompt for session [id]"*
- *"Update the prompt for session [id] to be more concise and avoid excessive praise"*

## Claude Code slash command

If you use Claude Code, you can also install the [harmonica-chat](https://github.com/harmonicabot/harmonica-chat) slash command for designing, creating, and managing sessions:

```bash
curl -fsSL https://raw.githubusercontent.com/harmonicabot/harmonica-chat/master/install.sh | bash
```

Then run `/harmonica-chat` for guided session design, or `/harmonica-chat "Topic"` for quick creation.
